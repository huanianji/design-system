## 1. 产品主线与本稿的位置

**长期目标：制作一个供维护者和 AI 长期使用的跨平台设计系统，帮助每个项目形成合适的视觉方向，将它实现为可用界面，并积累可复用的设计经验。**

主要使用入口是在 Codex 中描述需求，由 AI 按任务读取设计系统。目标平台包括 Web、桌面、Android、iOS 与 Godot；平台组件、实现方式和输入习惯允许不同。

品牌目标是：产品各有调性，用户第一眼能知道它们来自「华年集」。希望用户形成的印象为「很懂主播，也总能做出有意思、好用的东西」。软件扩大公会影响、软件收入反哺公会，是该产品体系的业务目标。

本稿负责定义共同语言、可变范围、组件打磨方向，以及 AI 使用这些规则的流程。完整系统还需要逐步具备以下能力：

| 能力 | 应形成的结果 |
|---|---|
| 理解产品与任务 | 明确用户、真实内容、关键操作、使用情境、平台与验收要求 |
| 形成不同视觉方向 | 在共同身份下探索有实质差异的构图、排版、素材、材质与动态表达，并说明取舍 |
| 维护共同身份 | 让品牌、字体与形状关系、交互手感在产品之间保持联系 |
| 实现可用界面 | 贯通主要流程、完整状态、真实数据边界、素材和平台交互 |
| 检查并精修 | 根据实际画面、操作与异常状态修正设计和实现 |
| 积累并按需复用 | 保存已认可的规则、主题、组件、案例、反例、证据和未决问题 |

共同规则是上述系统的一部分。启动动画、单套皮肤或现有 React 组件，都只能覆盖其中一部分能力。

## 3. 必须统一与产品自由的总表

本稿建议以**圆润且清楚的形态、带弹性的操作反馈、连续的状态转变、有功能含义的动态细节**作为共同基础。以下将其拆成可检查的约束。

| 维度 | 必须统一的部分 | 产品自由的部分 | 检查方式 |
|---|---|---|---|
| 品牌归属 | 产品名与各自已有 Logo 为主，搭配普通文字「华年集出品」；软件内不出现华年集 Logo，按 §3.6 | 产品主题、代表元素和适应平台的排布；已有 Logo 按本产品资产规范使用 | 能识别产品并通过文字确认归属；不嵌入母品牌图形/专用字标，不把引用规则存在写成界面已实现 |
| 字体与阅读 | 延续圆润、清楚的方向；核心界面采用共同字族和角色分工，展示/专业内容的配套例外按 §3.4，正式字库待验证 | 字号、字重、行高、密度、语言适配及角色允许的配套字形 | 检查中文、长文案、数字、混排、缺字和文字放大；字体不能只在展示样张里好看 |
| 形状与层级 | A 的圆润、非对称方向与角色分层按 §3.5；独立轮廓和主要操作稳定保留家族表达，轮廓、选中与焦点清楚 | 圆角幅度、框线与填充方式、材质、空间感、构图；小控件和专业区域按已确认边界简化 | 同类角色的形状关系有据可循，不能因主题变化丢失可操作性与层级 |
| 留白与分组 | 按实际边界保留净空，用距离表达内容归属，为焦点与运动预留空间；执行 §3.1 | 间距尺度、密度、非对称补偿与平台单位 | 检查直边、曲边、嵌套、长内容和运动极值，不能只确认 padding 数值相等 |
| 视觉对齐 | 以几何对齐为起点，结合图形重心、承载轮廓和组合关系作一致校正；执行 §3.2 | 各类图标的校正方向、幅度和适配方式 | 实际尺寸下看静态、动态与整组图标；视觉校正不挪动点击区域或焦点边框 |
| 按压与回弹 | 可操作控件及时回应按下、释放与结果；相近动作具有可辨认的弹性手感；禁用与忙碌状态准确 | 按钮、图标入口、卡片的幅度与速度；触控和手柄的表现 | 快速点击、长按、重复操作和状态变化时，反馈连贯且不影响操作命中 |
| 选择与焦点 | 当前选择、当前焦点与临时悬停各有清楚表达；切换后的内容与选择对应 | Tab、分段、侧栏、工具栏的布局，选中背景或标记的具体形态 | 鼠标、键盘及适用的触控/手柄都能看懂当前位置；焦点移动不误触业务动作 |
| 动态图标 | 同一功能含义稳定；图标静态形态与动态反馈成套设计；动作与触发原因对应 | 图标题材、局部造型、动作细节和表现强度 | 静止时能识别，运动时能理解；状态信息不能只靠动画表达 |
| 输入与确认 | 输入内容、焦点和验证状态的变化相互衔接；输入法、粘贴、更正和错误恢复可用 | 验证码分格、普通输入、搜索、编辑器等各自形态 | 验证动作与内容、焦点位置一致；真实验证结果决定成功状态 |
| 展开与收起 | 关系清楚，适合连续展开的对象保留来源；返回时恢复合理焦点与必要上下文；中途操作可接续 | 浮层、抽屉、面板、全屏及平台原生转场；位移、形变和空间表达 | 展开、切换、关闭和快速反向后，用户仍知道自己在哪、内容来自哪 |
| 状态与反馈 | 等待、成功、失败、空和未知各自准确；失败可观察，并提供适合任务的恢复路径 | 原位反馈、提示条、面板、通知等承载方式 | 动效结束不制造成功，失败不伪装为空态或零值，重试不丢应保留的输入 |
| 动态可用性 | 尊重减少动态效果的偏好；输入与阅读在动画中保持可用；循环、声音和演出的启停可控 | 是否使用氛围动画、粒子、3D、声音，以及适合场景的强度 | 关闭或减少动态后仍能完成任务；后台、退出和中断后的状态正确 |
| 内容与素材 | 来源、用途与归属清楚；软件界面、直播输出、素材、角色与作品包装分别规定品牌呈现范围 | 作品美术、世界观、角色风格、直播玩法与生成素材的视觉方向 | 工具能容纳不同内容风格；品牌资产与作品内容不会因复用组件而被强制混同 |

共同字体的具体建议是：先以共华年资源圆体为工具类正文的默认候选，连同缺字回退和数字阅读一起评估。品牌字标、作品标题、代码等专业内容及目标平台有明确需求时，可以采用配套字形；作用与原因需要记录。

共同形状不等于所有容器使用同一个圆角。共同运动也不等于所有控件使用同一条曲线、同一时长或同一回弹幅度。

### 3.1 留白协议

**共同原则已纳入；具体数值按产品与平台确定。** 适用于页面、面板、列表、表单、菜单、工具栏、画布周边和浮层等所有界面区域。留白同时解决边界安全、内容归属和操作空间，不能只修单个按钮。

1. **建立整体留白，再分别定义用途。** 从页面两侧、主容器到嵌套区域确定一致的宽松程度与内容对齐轴；保有舒展的阅读和操作空间，不能将刚好不碰边的最小距离当作视觉目标。至少区分容器内边距、同组内容间距、组间距和操作所需空间。以产品的间距尺度建立关系；通常同组更近、组间更远，特殊布局要有清楚的分隔或层级依据。不能用同一个 gap 代替所有关系，也不能靠给整个页面加空白掩盖局部拥挤。
2. **按实际轮廓检查净空。** 净空指可见内容到可见边界的最近距离。圆角、斜边、缺口和非对称轮廓会改变可用区域；直边的内边距相等，不代表曲边附近同样宽松。靠近收窄位置的文字、图形和操作区应退让，或调整局部布局/容器尺寸。需要主动出血的作品、背景等可以越界，但不能遮挡信息或操作，例外要有明确用途。
3. **协调嵌套形状与间距。** 平行内缩的圆角可从「内圆角 ≈ 外圆角 − 内缩距离」试调；不同角分别判断，随后检查实际轮廓。该关系只是起点，不能替代净空检查，也不要求非平行的子块机械使用减法。增加内边距后，重新核对内部尺寸和内容容量，避免子项被挤扁或文字溢出。
4. **把交互与运动算入空间。** 检查按压、回弹最大幅度、悬停、焦点边框、选中标记、展开和状态提示的位置。必要信息和操作反馈不能被裁切、盖住邻项或造成误触。点击/触控范围由目标平台与输入方式确定，不能为了视觉留白缩小命中范围；需要时增大容器或改排布。
5. **密度调整保留关系。** 窄窗口、触控、文字放大和长文案下，可以换行、重排、增加高度或按用途压缩间距。保留边界净空、分组和操作空间，不能按统一比例缩小全部内容。紧凑工具也应有可解释的密度规则。

验收时看内容与实际边界是否拥挤、分组是否清楚、交互是否安全，不能以「使用了间距令牌」替代实际画面判断。

### 3.2 图标与内容的视觉对齐

**共同原则已纳入；校正不固定为向左或某个像素值。** 适用于独立图标、状态符号、图文操作、导航项及其他需要对齐的内容。

1. **先建立几何基准。** 用稳定的图标画框、尺寸、笔画与对齐轴组织图标族，检查素材是否自带不均匀空白。优先修正错误的 viewBox/画框或素材，再作视觉微调；不能用每个页面随手加偏移来掩盖源图问题。
2. **同时看图形和承载形状。** 几何中心不一定是看起来的中心。笔画分布、实心/线框、方向性及容器的圆角、缺口、非对称轮廓都会改变视觉重心。以几何对齐为起点，在实际显示尺寸下比较相对边缘的空白和整组节奏，再作必要的小幅校正；无需修正时保持基准。
3. **按组合的职责对齐。** 独立图标在承载形状中校正；图标加文字应先检查整个组合的居中或起始对齐，再检查图标与文字的基线/视觉高度和间距。箭头、播放三角、勾选等方向性图形可以需要图形自身的校正。列表和工具栏保留统一的文字/布局轴，不能为居中某个图标挪动整行。
4. **一致性放在合适层级。** 图标本身的问题在图标资产层修正；某类容器的问题在该类容器统一处理；图文组合的问题在组合规则处理。同类尺寸、轮廓和用途共享校正依据，必要的例外注明原因。不要把 A 的右上角形状带来的左移推广到对称容器，也不要让所有图标套用同一方向。
5. **视觉位置与交互位置分开。** 微调图形或内容组合，保留稳定的布局、点击区域、焦点边框和语义。校正应与旋转、缩放、状态动画组合，避免动画覆盖校正、落定跳位或运动后重心改变。动效本身有意改变视觉重心时，检查起点、极值和最终状态。

验收至少对照实际使用尺寸、浅/深背景及相关状态的整组表现；测量偏移量只能证明实现了位移，是否平衡仍需看实际画面。

### 3.3 AI 实施、检查与记录

共同判断原则必须沿用；产品决定具体间距、密度、圆角、图标画框及光学校正值，平台决定单位与实际输入条件。后续 AI 制作新界面或精修时：

2. 实现时将内边距、组内/组间距离、曲边补偿与图标校正放在相应的可复用样式、主题或组件层。小范围可直接使用清楚的规则，不为此另建一套框架。
3. 检查受影响的代表界面：常用与窄尺寸、长内容或文字放大、浅深主题（产品有提供时），以及焦点、选中、回弹极值、展开和减少动效等相关状态。先测溢出、净空与命中范围，再看实际画面；模拟视口不替代目标设备验证。
4. 在原项目档案中记录本项目采用的尺度/校正依据、必要例外和实际验证，引用本节，避免复制共同规则。只有局部证据时只报告该范围，不能写成整个产品或全部平台已合格。

本轮来源是维护者对 A 预览的两条反馈及随后明确要求：将留白、图标视觉对齐作为通用问题处理，原则共用、数值可调；后续又要求统一加大留白。A 预览是应用案例，其间距和独立图标左移量均不作为跨产品常数；实现与检查见[留白与对齐记录](../packaged-status.md)及该节后续修订。Web 案例不代表 Godot 或其他平台已经实现。

**以下是更正前的历史提案，已终止，不得执行或继续要求维护者选择。** 当时将软件家族识别误解为新做母品牌 Logo，尚未制作任何样例。

**方向一：从「华」字提炼图记。**

- 字标采用端正、笔画清楚的圆润字形，以适中的笔画重量与均衡字距形成稳定感；在少量收笔或连接处加入 A 的柔和与轻微不对称，仍让三个字容易识读。

**方向二：两条圆带相扣。**

- 字标更饱满，转角更柔和，字距较舒展，保持稳定的阅读基线，传递容易接近的感觉。

- 动态可让两条圆带轻微相对移动后回稳，保持相扣关系清楚，避免为了演出使符号暂时失去原有含义。

**方向三：三片圆角花瓣。**

- 字标带轻微手写感，收笔更舒展，保留清楚字形与稳定排列，表达创作活力；不将该字标风格推广成全部界面文字。

### 3.8 状态颜色与浅深背景

**状态：2026-10-26 经维护者确认，作为共同规则沿用，具体色值与参数继续待验证。** 共同规定颜色用途、状态含义和语义色相方向；主题强调色可更换，基础背景限定为白/浅灰与黑/深灰两套中性色并提供切换。产品/平台在该边界内映射具体数值和层级，本轮不改预览或建立色值源。

**先分清四类用途：** 基础界面色承载页面、面板、文字和边界；交互强调色表达当前工具、选中、焦点及主要操作；语义状态色表达成功、警告、错误等结果；内容/业务配色表达作品本色、分类、图表和领域状态。主题负责协调它们，但引用角色应分开，不能只维护一个「主色」承包全部含义。

| 角色 | 共同色相方向 | 含义与边界 |
|---|---|---|
| 成功、需要明确表达的正常状态 | 绿色系 | 对应实际成功或正常结果；不强制把所有勾选、已完成条目或当前选择涂绿，选择可继续采用产品强调色 |
| 警告、需要关注的风险 | 琥珀/橙色系 | 事情需要注意但未必失败，配明确原因和适合的处理方式；不能与错误等同 |
| 错误、失败、无效输入 | 红色系 | 明确问题位置、结果和恢复方式，颜色跟随真实状态；保持错误文字可读，不靠整片红色替代说明 |
| 普通信息与说明 | 中性色或信息蓝色系 | 表达中性信息，不暗示成功；是否强调按重要性决定，不能把所有提示都做成警告 |
| 处理中、等待、尚未完成 | 产品强调色或信息色，配过程标识 | 区分正在工作和已经成功；未知进度不伪造百分比，结果未确认时不提前进入成功色 |
| 未知、空、未配置 | 中性色 | 用文案/符号分别说明，未知不补成零值，空不伪装成错误；灰色不能承包全部状态含义 |
| 禁用、暂不可操作 | 中性色与可辨的弱化层级 | 与忙碌、未选和未知分开，必要时说明原因；仍保留辨认所需的信息与状态 |
| 危险操作 | 独立的危险操作角色，可用红色系 | 提示动作后果，与已发生的错误分工；操作是否可用、是否需要确认由实际业务规则决定 |

**必须统一的判断原则：**

1. **含义与角色稳定。** 换主题不改变成功/警告/错误等含义；产品选用同一语义色相家族，具体颜色适配各自背景。业务状态先由产品规则定义，再映射色彩，不从红绿反推业务结果。
2. **选择、焦点、悬停、按下分别表达。** 选中可用产品强调色，焦点有稳定可见的独立边框或标记，悬停/按下按同一控件的层级变化。选中不代表成功，焦点不自动代表已选择，危险操作也不等同于错误结果。
3. **颜色配合其他线索。** 状态有清楚文案、图标、位置或形状，不能只靠色差传达关键信息。浅深主题分别检查文字、图标、边界与状态叠加；强弱层级不能靠把重要说明淡到难读来实现。
4. **产品色可以自由，功能含义仍要分辨。** 红、橙、绿等也可以是产品主题色；产品强调与语义状态分别定义，并通过明暗、承载方式、图标和文案形成区别。蓝紫色不是华年集统一主色，颜色自由不改变状态真实性。
5. **内容与领域状态另有用途。** 直播中的红色 LIVE 标记、分类颜色和作品里的红色都不能自动当作错误。分类与图表在产品内保持映射稳定并提供可理解的标识；沿用已确认业务语义，不拿通用成功/失败配色覆盖领域规则。
6. **主题不改变作品。** 切换工具主题只影响界面；素材、直播画面、色票和导出内容按自身数据与预览/输出规则呈现，不能自动套入界面强调色或状态色。

**基础背景与切换的共同约束：**

- 浅色形态以白、浅灰组织页面、面板和工具区；深色形态以黑、深灰组织这些区域。基础背景使用中性色，不随主题强调色变成整页或整块有彩工作底色；两套背景可通过中性灰阶、边界和阴影表达层级。
- 两类产品主题都必须提供浅色/深色切换；管理/创作是任务组织维度，背景明暗是独立维度，不能用管理浅色、创作深色代替两类各自的双形态。
- 主题强调色和语义色继续用于操作、选择、焦点、边框、图标及相关局部反馈；与基础背景角色分开。作品、素材和直播画面的本色不受中性背景限制，也不随工具主题改变。
- 切换后当前任务、输入、选择和业务状态保持，文字、图标、边界、焦点及状态在两种背景下均清楚；具体切换入口、灰阶、过渡和平台映射在后续实现中验证。

**产品/平台可自由调整：** 主题强调色、语义色的具体色值及承载方式、中性色背景范围内的层级与材质、文字/图标强弱及布局；平台映射实际渲染。最终数值维护一份清楚的角色源与主题引用，浅深形态分别映射，不能另抄多份相互漂移的颜色表。当前未选择色值或实现令牌。

后续建议用选中叠加焦点、错误/警告与产品主色同屏、等待转结果、未知/空/禁用，以及真实内容预览进行比较；本轮未制作这些样例或取得对比度/两端呈现验收结果。

## 4. 运动语言怎样落入日常界面

**状态：2026-10-26 经维护者确认，作为共同规则沿用，日常级作为默认。** 已确认运动角色、节奏关系、强度分级及共同/自由边界；具体参数继续待验证。本轮仅更新规则，不启动实现或参数冻结。共华年与 A 的现有代码只作为参考，不代表这些分级已经在各产品实现。

共同性格是：操作一发生就有回应，变化过程能追踪，适合弹性的动作有清楚回弹，最后落稳。共享动作的因果、角色与节奏关系，产品和平台分别确定具体幅度、时长与曲线。

### 4.1 先按用途区分运动角色

| 角色 | 帮助用户理解什么 | 共同表达及边界 |
|---|---|---|
| 触感回应 | 操作已经被接收 | 按下及时轻压，松开弹起落稳；勾选可配合底形与勾线。相称于尺寸，含内部操作的卡片避免父子同时重复回弹 |
| 选择与定位 | 当前选在哪里、焦点移到哪里 | Tab/分段标记、导航与验证码焦点可连续迁移；焦点与选择含义保持清楚，切换内容遵循实际模式，不因动画误触业务动作 |
| 空间与收展 | 内容从哪里来、展开到哪里、怎样返回 | 面板、详情和浮层保留可追踪的来源关系；按用途使用位移、形变或淡入淡出。系统导航按平台，不能强行为所有页面套来源展开 |
| 输入与内容变化 | 什么内容刚进入、被替换或更新 | 验证码数字进入、数值变化、列表局部更新有清楚落点；连续输入保持稳定，长文不逐字跳动，拖动和参数读数准确跟随实际值 |
| 过程与结果 | 正在等待、实际完成还是遇到问题 | 等待反馈与真实过程对应；成功/失败在相关位置表达，图标局部动作可强调含义。真实结果决定状态，动画结束不制造成功，错误说明持续可读 |
| 情绪与场景表现 | 成果、玩法或作品有哪些值得感受的内容 | 成就、创作结果、直播玩法和氛围可有更完整的演出与联动；明确触发、播放范围和结束/启停方式，表现服从具体内容 |

同一交互可以涉及多个角色，但要有一个主意图并统一编排。例如勾选的触感和结果相互配合，不能堆叠互相打断的动画。动态图标按用途归入角色：铃铛可提示事件，加载图标表示过程，状态图标表达结果；不将所有图标都设为周期摇摆。

### 4.2 节奏关系

- **回应直接。** 按压、选择、焦点和输入及时回应，业务处理和下一次操作无需等待收尾动画；等待状态也不能依靠一段前奏才显现。
- **按压快接收，释放有回弹。** 适合触感的控件可以清楚弹起，再逐步稳定；高频操作缩短余振，避免一个动作未落稳又排队播放多次旧动作。
- **选择先明确，移动可追踪。** 选中状态即时成立；标记和内容的视觉变化协调接续，避免先清空整块内容再等待入场。精细定位的标记停在准确位置。
- **展开给理解过程，收起利于返回。** 起势直接，中段连续，末端稳定；收起通常可以更利落，但仍保留来源关系。位移距离与内容规模可以影响时长，不要求大面板和小图标同速。
- **直接操控跟手。** 拖动、滑块、调色和时间轴在操作中准确跟随输入；释放后的反馈可以有性格，不能让读数或真实落点因回弹而失真。
- **结果跟随事实，演出有主次。** 等待随任务持续，结果确认后再表现完成；同一操作链由主要对象带动相关元素，其他内容保持可读和可操作。连续通知合并或更新反馈，避免旧提示动画排队抢占注意。

本轮不设统一毫秒数、缩放比例、弹簧参数或统一曲线。当前预览中的按压、勾选、图标和展开参数也不自动成为基准；后续用同内容、同状态的实际片段比较短动作、较大收展和快速反向。

### 4.3 按场景分配强度

| 分级 | 适用场景 | 共同表现 |
|---|---|---|
| 精确级 | 密集数据、连续输入、拖动调节和高频专业操作 | 保留清楚的按压/选中反馈，幅度与余振较小，内容和落点稳定，直接操控跟手 |
| 日常级（默认） | 主要按钮、Tab、面板收展、常用图标和确认反馈 | 有辨识度的弹性、位移和形状接续，动后落稳；作为华年集日常手感，不把鲜明反馈只留给庆祝场景 |
| 表现级 | 成就、成果展示、首次引导、直播互动与作品演出 | 允许较大运动、多层联动、场景节奏及适合内容的表现；能退出或控制播放，不让高强度覆盖普通操作 |

强度按界面区域和动作选择，不给整个产品永久绑定一档。共华年的主要按钮可用日常级、表格更新用精确级；光影集参数调节用精确级、面板切换用日常级；白宝集控制界面用日常级，直播输出可以采用表现级。产品主题可以调节整体强弱，但要保留同角色的家族联系。

减少动态效果是单独的可用性模式，不是品牌强度中的最低档。该模式优先减少大位移、反复振荡和多层运动，以状态、边框、颜色及适合的短过渡或即时更新保留操作含义；仍能读懂选择、焦点、等待和结果。

### 4.4 共同与自由的边界

| 必须统一 | 产品/平台可调整 |
|---|---|
| 动作与触发、真实状态及功能含义一致，视觉反馈不阻塞业务处理 | 使用哪些动态图形、位移、形变、材质变化和局部部件动作 |
| 相同角色共享回应、接续和落稳的节奏关系，适合弹性的日常动作有家族触感 | 实际时长、幅度、曲线、空间尺度、装饰和场景化表达 |
| 来源、方向和最终位置有依据；快速反向从当前可见状态接续 | 平台原生转场、触控/键盘/手柄的映射，以及不同输入方式的表现 |
| 相关动画有主次，输入/阅读/焦点持续可用，运动范围与已确认留白相容 | 按区域和操作选择精确、日常、表现级，可按产品主题调整强弱 |
| 状态可静态辨认，提供适用的减少动态、暂停和结束方式 | 循环、氛围、声音或场景演出的采用与控制形式；按内容需要决定 |

### 4.5 中断、恢复与直播边界

快速重复与反向优先更新到最新意图，从当前显示状态接续；动画不积压，结果不闪回旧状态。业务是否允许重复操作仍由真实业务规则决定，视觉可重播不表示请求可以重复执行。

展开过程中不产生重复交互目标；关闭后合理恢复焦点、滚动、草稿及适用的媒体状态。退到后台、退出或取消时清理无意义的运动；任务仍在进行时保留正确状态，暂停视觉不等于暂停任务。

直播控制界面和观众看到的输出场景分别规定运动范围。控制操作的反馈不自动进入直播输出；持续的玩法/氛围按作品用途运行，由主播控制启停及输出。声音若被采用，需有符合场景的触发和控制，不能从视觉分级推导为默认自动播放。

### 4.6 后续 AI 怎样应用

先按任务识别主运动角色，再按操作频率、精度、空间规模和内容用途选择强度；定义触发、真实状态、起点/终点、节奏、反向/中断、结束与减少动态表现。平台数值与必要例外在项目档案中记录，原理引用本节，避免为每个界面另写一套解释。

角色划分、日常级作为默认、精细操作与表现性场景的分级及共同节奏关系已确认。具体参数、双端消费、组件实现和实际手感验证继续按 P2/P3 范围安排，不因文档存在宣称完成。

白底、品牌紫、三栏骨架、共华年的紧凑字号、固定列表尺寸和财务专用色，不作为华年集全产品的必选项。具体产品仍遵循自己的业务与权限规则。

### 5.1 管理型与创作型主题方向

**状态：2026-10-26 经维护者确认，作为共同方向沿用；具体色值和参数继续待验证。** 两类按任务组织内容与操作，均继承字体角色、A、留白/视觉对齐及运动规则；基础背景只用浅色白/浅灰与深色黑/深灰，均须提供切换。产品各自已有 Logo 保留，软件内不展示华年集 Logo，「华年集出品」为普通文字。本轮不创建主题实现、组件或综合界面。

| 维度 | 管理型方向：清楚、有序、便于处理 | 创作型方向：内容居中、便于试验与比较 |
|---|---|---|
| 主任务 | 看清状态，筛选、比较、定位问题和处理事项 | 看清作品/内容，浏览、编辑、调整、比较与输出 |
| 组织与布局 | 围绕任务、列表/表格、摘要和详情建立稳定的阅读与操作顺序；支持适合任务的批量操作 | 把作品、素材、画布或其他主要内容放在视觉中心，工具与参数围绕当前任务组织；面板按任务收展，画布只是内容形态之一 |
| 留白与密度 | 外围与组间舒展，组内有序紧凑，比较对象对齐；保留已认可的边界净空和操作空间，紧凑不靠挤压或过小文字 | 给作品与比较区域更多空间；工具区可紧凑、精确，素材浏览和结果展示按内容留白；不要求所有按钮或区域都放大 |
| 配色倾向 | 以白/浅灰或黑/深灰的中性层级承载数据，强调色标出当前操作，状态色放在相关信息处 | 作品和工具周边同样采用两套中性背景，强调色标出当前工具/素材；内容本色独立，布局与局部表达保留产品性格 |
| 层级与材质 | 文字、边界、分组和局部承载面清楚；通过层级而非把每条信息包成卡片来组织界面 | 可在适合的区域使用更丰富材质、空间感和大幅内容；精细判断区域保留清楚背景和稳定边界，不让装饰影响内容判断 |
| A 的表达 | 在主面板、主要按钮、导航/Tab 等独立轮廓中体现；表格与连续列表内部可以规整简洁 | 在工具面板、常用操作和独立浮层中体现；作品比例、画布边缘与精细工具按内容和功能处理 |
| 动效 | 日常级仍是默认；主要操作保留明显弹性，表格刷新、连续输入和高频调节按精确级处理 | 工具切换、面板和普通操作使用日常级，拖动调参使用精确级，成果或直播玩法可采用可控的表现级 |

**两类共同保持：** 同样角色的含义与家族关系，真实状态、清楚焦点与可操作性，以及稳定的文字和形状角色。管理型可以活泼，创作型也需要精确；布局、密度和材质的区别服务于任务，不以削弱已确认动态或留白为代价。

**产品自由与混合：** 主题强调色可更换，中性背景约束内的层级与材质、内容美术、密度和版式自由；基础背景不扩展为其他彩色方案，两类均须提供浅深切换。各产品可按页面或区域结合两类组织方法，同时保持产品身份与状态映射稳定，避免每进一个页面就换一套身份。

共华年式任务管理可作为管理方向参考，光影集/米鹿工坊式内容与参数工作区可作为创作方向参考；主题组织关系已确认，但这不代表已选定真实接入项目或产品技术栈。一个创作产品中的记录列表也可采用管理型组织，管理产品中的内容预览也可采用创作型组织。

**后续 AI 应用：** 先读项目现有主题与业务状态，再识别当前页面的主任务，选择组织方式；定义颜色角色后再选择色值，明确哪里保留 A、哪里按精度简化，以及各区域的运动强度。在原档案记录方向、理由、自由项和例外，引用共同规则，不为不同产品机械复制同一页面。

语义颜色家族、管理/创作两类任务组织及共同/自由范围已确认，并按最新要求补入强制的浅深中性背景切换。后续通过实际片段验证具体调色板、密度和布局参数；完整综合界面仍按 P4 推进，当前不宣称主题、令牌或 Web/Godot 适配已经实现。

## 8. AI 如何使用这套系统

这是 AI 调用流程的共同要求。P1 已建立 [Skill 入口](../../SKILL.md)、档案模板及只读资源定位脚本，当前状态见[验收记录](../packaged-status.md)。尚无自动生成界面、主题或组件的完整工具。

本节保留共同规则对 AI 工作方式的要求；入口结构、任务分支、读取路线和首版验收范围详见[系统结构与首版交付](系统结构与首版交付.md)，避免将原则说明误读为已实现的调用机制。

1. **理解任务边界。** 明确本次是讨论、设计草案、界面实现还是局部修复；读取产品用户、真实内容、平台、已有决定与项目规范。已确认的信息与授权沿用，不反复要求确认。
2. **按需读取。** 读取本稿，再读取当前产品主题、所需平台规则与相关组件/案例；不把所有资料和全部平台一次塞入上下文。
3. **判断是否需要新方向。** 维护已有产品时延续已认可主题。新产品或明确改版时，提供有实质差异的方向，让维护者能比较构图、排版、素材与动态表达；单纯换色不算不同方向。
4. **记录选择及适用范围。** 明确本项目保留哪些共同特征、哪些由产品变化、哪些按平台处理；未选方案仍是实验。会影响产品身份或任务结果的关键决定先对齐，普通实施细节按授权推进。
5. **实现完整操作。** 优先复用合适的现有代码、平台能力和资产；实现主要流程与必要状态。样例、真实业务与数据边界清楚，不能用演示代替真实接入结果。
6. **检查并精修。** 看实际界面与交互，对照共同身份、产品用途和平台条件；按 §3.1—3.3 检查留白、视觉重心及运动后的边界。动效看录屏或实际操作；数据/外部服务改动验证相应主路径。仅运行类型检查不构成功能或视觉验收。
7. **交付与沉淀。** 给出实现入口、验证结果与限制，将确认后的决定和可复用经验写入已有单源。复用失败、未采用方向和待核事项保留清楚状态，不能自行提升为长期规则。

项目设计档案至少应能回答：产品给谁用、主要任务是什么、视觉方向为何合适、继承了哪些共同规则、平台怎样适配、关键状态怎样表现、素材从哪里来，以及哪些检查实际完成。优先沿用项目已有设计文档，不另建重复台账。

## 9. 复用资产怎样积累

建议以「共同规则 → 产品主题 → 平台实现与案例」组织后续资产；实现可以因平台而不同，来源和决定可以追溯。

| 资产 | 至少记录什么 |
|---|---|
| 共同设计规则 | 规则内容、适用范围、来源、确认状态及变更原因 |
| 产品主题 | 产品任务、视觉方向、共同特征的表达方式、产品自由选择与平台差异 |
| 令牌 | 颜色/字体/形状/运动等角色含义、值或引用、主题与平台映射；行为规则另有说明 |
| 组件与交互模式 | 解决的问题、状态与输入、动作、可打断性、减少动效、平台入口、源码与验证情况 |
| 素材 | 来源、使用条件、目标用途，以及是否属于品牌资产、示意素材或作品内容 |
| 案例与反例 | 固定的场景和内容、实际画面/录屏、发现、修订及维护者的具体反馈 |

按「参考」「实验」「已确认」「待复验」区分状态。代码存在、自动检查通过、用户认可方向、某个平台可用，是不同的证据，不能互相替代。某产品的试验不会自动变成全产品规范。

初期本地文件可以承载这些记录；只有出现明确的检索、同步、预览或资产操作需求时，再讨论增加工具接口。当前不据此新增 MCP、服务、依赖或发布流程。

## 10. 如何判断这套系统是否成立

| 要检查的能力 | 可观察的证据 |
|---|---|
| 品牌归属 | 用户能找到华年集身份；不同产品存在具体可指认的共同特征。第一眼辨识度仍需在具体标识与形态形成后检验 |
| 风格多样 | 使用相同真实内容比较方向时，构图、排版、素材、形状或动态关系存在实质差异；选中方向符合产品任务 |
| 操作可用 | 主要操作、键盘/触控/手柄等适用输入、文字阅读、异常与恢复在实际界面检查 |
| 动态质量 | 按压、切换、展开及连续操作有清楚因果，运动可接续，减少动效仍可完成任务；记录具体设备与观察范围 |
| 跨平台 | 相同设计意图在目标平台分别实现并验证；保留平台差异说明，不能只用 Web 截图宣称全平台支持 |
| 长期可复用 | 新增页面或更换 AI 会话后，能从已有记录延续决定；复用资产有来源和状态，经验能找到并实际用于后续任务 |
