# 雨伞设计

目标是帮助不同项目形成合适方向、实现可用界面，并保存可复用经验。保留各产品调性，使华年集归属清楚。当前可用资源与未实现能力以资源清单为准。

## 先定位，再读取

以本文件的真实目录为基准运行 `python3 scripts/kit.py context --project <目标项目绝对路径>`；在其他工作目录中使用该脚本的绝对路径。该命令只读，目标必须是已存在的目录，路径错误会明确失败。不要把目标项目目录误当作 Skill 根目录。

按返回的 `resolved_path` 打开资源，以原文所在目录解析相对引用；`references/` 中的中文入口页只指向原文，不承载另一份规则。定位命令只探测三种默认档案名称；用户已指定其他单源时直接使用该文件，不运行初始化。

1. 读取目标项目规范及已有设计档案；已有认可决定直接沿用。
2. 读取 [资源状态](references/resources.json) 和[共同规则原文](references/common/华年集共同设计规则.md)，只展开当前任务相关条目。
3. 根据任务读取 [档案使用规则](references/project-record.md)、[方向方法](references/direction-guide.md) 及目标平台资料。不要为单个平台读完所有平台。
   新建界面、改版或参考复现时，按方向方法打开相关[视觉参照](references/visual-baselines/index.md)，实际查看图片或运行样例；仅阅读规则和数值不足以建立视觉目标。用户自己的已选基准优先于通用案例。
   实现或修改 Web/Godot 共同视觉时，按[共同源与生成说明](references/shared-foundation.md)读取唯一数值源、产品覆盖和平台映射，生成后核对实际消费。已有公共交互和组合样张按资源表复用；尚未覆盖所有控件，不直接覆盖未经采用的产品主题。
   界面实现、精修或对照已有基准时，按[交互差异排查](references/interaction-review.md)明确本次受影响部分的交互边界与状态归属，核对平台继承默认值，再通过同条件、同操作路径的实际画面验证。新控件未入库时同样适用；无需为小修重建全项目档案。
   复用公共交互时从资源状态定位按钮/Tab/展开、输入/验证码和动态图标；组合任务读取[工作台与AI消费](references/combined-workflows.md)，日常示例由[展示入口](foundation/web/showcase.html)定位到Web及对应Godot场景。示例演示数据和模拟失败开关不直接移入真实产品。
4. 结构与阶段范围只有讨论系统本身时才读：[系统结构原文](references/common/系统结构与首版交付.md)、[实施路线原文](references/common/首版实施路线与验收.md)。历史实验和共华年源码按需要溯源，不是每次必读。

## 选择工作方式

| 任务 | 工作方式与产出 |
|---|---|
| 新产品或明确改版 | 先明确本次视觉目标、可重新设计的区域和需保留的业务行为。用户已要求制作或改版即已有相应实现授权；方向足够明确时连续完成，不再以讨论流程重复索要同一授权。整页改版可重组该页布局、层级、留白与控件，不把它降格为换色或微调。 |
| 按参考复现 | 实际查看指定基准，提取构图、比例、密度、字体、形状和状态关系，再在目标平台实现。先处理整体，再处理局部；不能用读过相同令牌或复用少数控件代替画面对照。 |
| 已有产品继续设计 | 先读档案，区分明确认可的选择与仅仅存在的旧实现。保留未被新要求改变的已认可决定；用户要求改版时，旧布局不是自动冻结的约束。 |
| 局部精修或修复 | 读取相关实现及模式，解决具体问题并检查受影响状态；保持其他已认可选择。没有实现时明确说明，不能声称已修复。 |
| 只读设计检查 | 读规范与实际材料，区分事实、建议、待核，给出位置和证据；不修改档案、代码或共享规则。 |

对“优化界面”等较宽请求，先用简短说明给出将调整的范围与预期可见变化，再在既有授权内推进。只有会改变结果的关键方向缺失才询问；不要默认为只改最少的样式。实现改动应与用户目标相称，业务流程、数据归属和已确认功能继续保留。

## 设计判断

- 品牌目标是“懂主播、有意思、好用”。圆润字形、按钮回弹、Tab/选择、动态图标、输入/验证码及连续展开是重点参考。现有全部参数和共华年整库未被批准为共同规范。
- 产品强调色、布局、密度、素材和动态强度可变化，状态含义与语义色相按共同规则；页面/面板/工具区基础背景只采用白/浅灰与黑/深灰两套中性色，并须提供浅深切换。共华年的紫色与三栏不是全产品默认。各软件使用自己的已有 Logo，不放华年集的图形、专用字标或组合标识；「华年集出品」为普通文字署名。
- 新方向要体现在构图、层级、内容组织、材质或动态关系上；用日常操作解释动效，不能仅展示 splash 或换色。
- 共享交互意图，各平台分别实现。读取当前平台状态；缺少实现时如实列出，不把平台文档、浏览器缩放或模拟成功写成适配完成。
- 动效与实际状态、输入及操作结果对应，支持必要的中断与恢复；用户喜欢鲜明动态，也应保留阅读、输入和减少动态效果的可用性。
- 共用令牌或业务断言通过，不能证明界面细节一致。对用户路径检查实际点击 / 键盘、选中与焦点叠加及动作后的画面；记录未执行状态和有依据的平台例外，不能将程序直接调用状态函数算成点击验证。
- 界面实现与精修按任务读取[共同规则](references/common/华年集共同设计规则.md)：留白、视觉对齐、字体角色、A、运动、§3.8 状态颜色及 §5.1 两类主题方向已确认，日常级为默认，具体字体/色值/参数待验证。§3.6 处理已有产品 Logo 与文字署名；§3.7 的新母品牌 Logo 提案已终止，不得重启或作为验收前提，历史预览不覆盖现行规则。

## 保存和接续

### 首次交付前

按[方向方法的画面复核](references/direction-guide.md#首次交付前的画面复核)运行本次真实页面或场景。将参考、改前、改后放在相同条件下看，先判断整体视觉目标，再检查真实操作及动态过程。发现的问题由本次执行者继续修改和复验，不把能自行发现的逐项问题留给用户再催一轮。

编译、结构检查和既有样张测试只说明各自覆盖范围，不能代替新页面的视觉检查。无法运行或查看时写清缺口；已知目标没达到时继续处理或说明具体阻塞，不能报告已还原或已完成整体验收。

### 档案写回

按 [档案使用规则](references/project-record.md) 维护目标项目的单一设计档案。新项目可用 [档案模板](templates/PROJECT-DESIGN.md)，或运行 `python3 scripts/kit.py init-record --project <路径> --name <名称> --purpose <用途>`；检测到默认名称的已有档案时拒绝另建副本。

记录用户明确要求、AI 建议、已选方向、待定项、实际验证、来源和下一步。只更新本次相关位置；通用规则和系统运行条件用链接引用，保留本项目的差异与验证。主题未知时写待定，不替用户补造裁决；测试项目的要求不得提升为全产品规则。

每次交付说明本次完成范围、可检查入口、实际验证和仍未解决的事项。独立新会话应能仅从文件继续工作；不能依赖原聊天或冒称模型永久记忆。

共享规则变更另行确认。当前任务记录不自动改写个人记忆、全局规范、其他产品或安装配置。

## 插件安装与目标电脑

本目录是自包含插件的一部分。首次使用运行 `python scripts/portable.py doctor`，不要调用 `kit.py install` 的开发机链接功能。需要生成主题时仍使用本目录 `foundation/build.py`，由 PATH 或 `--godot` 选择该电脑的引擎。

设计规则与公共实现属于已安装插件；项目档案、产品覆盖、业务代码和验证结果属于目标项目。先读取用户指定项目，旧项目未授权时不自动套用主题，不把演示布景或本地模拟业务搬入真实软件。产品经验只提升其已确认的判断原则，案例中的间距与按钮形式不作为所有产品固定值。

预览：`python scripts/portable.py prepare --case foundation|lumina --target <尚不存在的新目录>`，再使用该电脑上的 Godot 导入。Web 在新复制的 foundation 根目录运行本机 HTTP 服务，打开 `web/showcase.html`。脚本需要 Python 3.9+；发现环境缺失时先说明实际条件，不推断其他电脑已经通过。
